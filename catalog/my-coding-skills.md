## 推荐理由

把个人编码工作流整理成一套可复用能力：设计、按需业务验证、统一工程原则、决策追问、仓库内经验积累，以及明确指定后的外部 CLI 调用。开发由当前 Agent 遵循 `eng` 原则完成，不规定固定流程。

## 什么时候用

需要具体设计决策、业务规则检查或验收、软件工程判断、深入追问方案，或调用指定外部 CLI。例如：“$eng 看一下这个支付回调的幂等写入约束。”

`design` 负责 UI 和交互设计；独立架构图或流程图可使用 Diagram Design。`eng` 是所有开发任务的统一工程入口；`reflect` 从日常纠正、失败和有证据的改进中学习，经验默认留在仓库，全局记忆仍需明确要求。`verify`、`grill-me` 和 `external-cli` 按各自定义的明确请求触发，不因打包而改变。

## 使用与验证

插件不会替你安装外部 CLI。已有独立安装的同名 Skill 时，选择一种安装方式，避免重复加载。当前验证范围是来源一致性、文件完整性与插件结构；未在新任务中验证插件命名空间下的跨 Skill 路由，也未运行外部 Agent。
